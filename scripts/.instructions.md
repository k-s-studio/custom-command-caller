# ccc.ps1 機制說明

## 執行流程

```
ccc <command> [extra-args...]
  ↓
讀取 cccrouter.json
  ↓
掃描指令模板裡的 $VAR → 驗證全部都在 params 且非空值
  ↓
解析位置參數 {0}, {1}, {n=default}
  ↓
以隔離 scope 執行 scriptblock
```

## 參數驗證

ccc 用以下 regex 從指令模板掃描需要驗證的 param：

```
\$\{([A-Za-z_]\w*)\}
```

只有 `${VAR}`（必須帶大括號）會被當成「ccc 管理的參數」，必須在 `params` 裡宣告（可為空值，但要有鍵），執行時也只有這些變數會被注入到隔離 scope。

裸寫的 `$VAR`（不帶大括號）、`$env:VAR`、PowerShell automatic variable（如 `$PROFILE`、`$HOME`）、以及一般 PS 賦值 `$x = ...` 都**不會**被掃描，也不會被注入——它們會落回 PowerShell 原生的 global scope / process 環境變數解析。

```jsonc
// ✅ 直接讀系統既有值，不需要在 params 宣告，也不會被 ccc 的 params 蓋掉
"cmd": "notepad $PROFILE"
"cmd": "code $env:USERPROFILE/projects"

// ✅ 中間值可用一般 PS 賦值；${PCKG_DIR} 仍是 ccc 管理的參數
"cmd": "$pkgDir = Split-Path ${PCKG_DIR}; code --install-extension $pkgDir/foo.vsix"
```

**結論**：只有 `${VAR}` 會觸發 ccc 的參數驗證與注入；其餘 `$` 用法照 PowerShell 原生規則運作。

## 執行隔離 scope

```powershell
$variables = [System.Collections.Generic.List[psvariable]]::new()
foreach ($param in $config.params.PSObject.Properties) {
    $variables.Add([psvariable]::new($param.Name, $param.Value))
}
[scriptblock]::Create($commandText).InvokeWithContext($null, $variables, $null)
```

scriptblock 執行時只注入 `params` 裡定義的變數，不繼承 ccc 本身的 PS 狀態。  
PS 的字串插值（`"$(...)"`）與管線在 scriptblock 內完全正常運作。

## 位置參數語法

| 語法 | 說明 |
|------|------|
| `{0}` | 第一個額外參數（必填） |
| `{0=default}` | 有預設值，可省略 |
| 超過 placeholder 數量的參數 | 直接接在指令尾端 |

```jsonc
// ccc git-uncommit        → git reset HEAD~1 --soft
// ccc git-uncommit --hard → git reset HEAD~1 --hard
"git-uncommit": "git reset HEAD~1 {0=--soft}"
```

## 撰寫需要切換目錄的指令

ccc 永遠在 `cccrouter.json` 所在目錄（專案根目錄）執行。  
若指令需要在子目錄執行（例如 `vsce package`），用 `Push-Location` / `Pop-Location`：

```jsonc
"hler-pack": "Push-Location (Split-Path $PCKG_DIR); npx --yes @vscode/vsce package; Pop-Location"
```

`Split-Path $PCKG_DIR` 從 `editor/vscode-cccrouter-syntax/package.json` 取出父目錄，  
`$PCKG_DIR` 符合 regex 因此正常通過 param 驗證。

## 安裝機制

`install.ps1` 做了三件事：
1. 把 `ccc.ps1` 複製到 `~/.ccc/`
2. 把最新的 `cccrouter-syntax-*.vsix` 複製到 `~/.ccc/cccrouter-syntax.vsix`
3. 建立 `ccc.cmd` wrapper（讓任何 terminal 都能呼叫 `ccc`），並把 `~/.ccc` 加進 user PATH

## Highlighter 更新流程

修改語法定義後：

1. 升版 `editor/vscode-cccrouter-syntax/package.json` 的 `version`
2. `ccc hler-pack` — 切到 extension 目錄打包成新版 `.vsix`
3. `ccc hler-install` — 讀取目前版本號，安裝至 VS Code
   （或直接 `ccc hler-update` 一步完成）
4. 之後再跑 `scripts/install.ps1` 時，新版 `.vsix` 會自動被打包進 `~/.ccc`
