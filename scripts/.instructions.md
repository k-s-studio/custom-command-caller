# ccc / ccc-router 機制說明

## 兩個指令
- `ccc <command...> [args...]`（`ccc.ps1`）：純路由。讀 `cccrouter.json`，把指令映射成 powershell 指令並以隔離 scope 執行。
- `ccc-router`（`ccc-router.ps1`）：管理用途——`init` / `install` / `uninstall`。

## ccc 執行流程

```
ccc <command...> [args...]
  ↓
讀取 cccrouter.json
  ↓
逐 token 走 commands 樹（value 是物件→命名空間，繼續往下；是字串→這是一條指令）
  ↓
解析命中 key 的簽章「<name> ^0=def ^1=def」，用 CLI args 依序填 ^0,^1…
（缺值用簽章預設；再缺則送進 powershell 前報「缺少參數 ^n」）
  ↓
回顯 > <實際指令>（設定在 params 的 $VAR 會顯示成實際值）
  ↓
以隔離 scope 執行 scriptblock
```

## 路由與簽章

- key 的「第一個空白前 token」是 routable 名稱：`"uncommit ^0=1 ^1=--soft"` → `uncommit`、`"git"` → `git`。路由時逐 token 比對這個名稱。
- 其餘 token 是位置參數宣告：`^n`（必填）或 `^n=default`（可省略）。預設值可引用 `$VAR`，會用 `params` 的值展開（例：`^0=$DEFAULT_MIGRATION_NAME` → `AAAA`）。
- value 用 `^n` 引用位置參數，可重排、可夾在字面值中間（`git reset HEAD~^0 ^1`）。
- 超過簽章宣告數量的 CLI 參數，直接接在指令尾端。

```jsonc
// ccc git uncommit 3        → git reset HEAD~3 --soft
// ccc git uncommit 1 --hard → git reset HEAD~1 --hard
// ccc git exclude           → 報錯：缺少參數 ^0
"git": {
    "uncommit ^0=1 ^1=--soft": "git reset HEAD~^0 ^1",
    "exclude ^0": "Add-Content .git/info/exclude ^0"
}
```

## 參數（params）變數

事前 regex 驗證**已移除**。`$VAR` 的處理規則：

- value 裡的 `$VAR` / `${VAR}` 在執行時由 powershell 在隔離 scope 內展開；`params` 同時也會 export 成 process 環境變數，供指令 spawn 的子程序（dotnet/EF 等）透過 `$env:...` 讀取。
- 沒在 `params` 設定的 `$`（automatic variable `$PROFILE`/`$HOME`、`$env:VAR`、一般賦值 `$x = ...`）照 powershell 原生規則運作，不受 ccc 干涉。
- `${VAR}`（帶大括號）在需要界定變數名邊界時仍必要，例如 `${EXTS_VERSION}.vsix`——裸寫 `$EXTS_VERSION.vsix` 在 scriptblock 會被當成對 `$EXTS_VERSION` 的 `.vsix` 成員存取而壞掉。

```jsonc
// ✅ 讀系統既有值，不需在 params 宣告，也不會被 ccc 的 params 蓋掉
"profile": "notepad $PROFILE.CurrentUserAllHosts",
"open":    "code $env:USERPROFILE/projects",

// ✅ 中間值可用一般 PS 賦值；${VAR} 仍是 params 管理的變數
"pack": "$dir = Split-Path ${PCKG_DIR}; code --install-extension $dir/foo.vsix"
```

## 回顯

執行前印 `> <實際指令>`：其中設定在 `params` 的 `$VAR` / `${VAR}` 會替換成實際值（所以你看到的就是 powershell 會收到的內容），未設定的（如 `$PROFILE`）保留原樣交給 powershell。

## 執行隔離 scope

```powershell
$variables = [System.Collections.Generic.List[psvariable]]::new()
foreach ($param in $config.params.PSObject.Properties) {
    $variables.Add([psvariable]::new($param.Name, $param.Value))
    [Environment]::SetEnvironmentVariable($param.Name, $param.Value, "Process")
}
[scriptblock]::Create($resolved).InvokeWithContext($null, $variables, $null)
```

scriptblock 執行時只注入 `params` 裡定義的變數，不繼承 ccc 本身的 PS 狀態。字串插值（`"$(...)"`）與管線在 scriptblock 內完全正常運作。env var 只設在 ccc 這個短命 process，不會外洩到使用者 shell。

## 位置參數語法

| 語法 | 說明 |
|------|------|
| `^0`（value 裡） | 引用第一個位置參數 |
| `^0`（key 簽章裡） | 宣告為必填位置參數 |
| `^0=default` | 簽章裡帶預設值，可省略；預設可為 `$VAR` |
| `^0=` | 預設為空字串 |
| 超過宣告數量的參數 | 直接接在指令尾端 |

## 撰寫需要切換目錄的指令

ccc 永遠在 `cccrouter.json` 所在目錄（專案根目錄）執行。
若指令需要在子目錄執行（例如 `vsce package`），用 `Push-Location` / `Pop-Location`：

```jsonc
"ext-update": "Push-Location ${EXTS_DIR}; npx --yes @vscode/vsce package; Pop-Location; code --install-extension ${EXTS_DIR}/cccrouter-syntax-${EXTS_VERSION}.vsix --force"
```

## 安裝機制

`install.ps1`：
1. 把 `ccc.ps1`、`ccc-router.ps1`（及 `install.ps1` / `uninstall.ps1` / `install-highlighter.ps1`）複製到 `~/.ccc/`
2. 建立 `ccc.cmd`、`ccc-router.cmd` 兩個 wrapper（讓任何 terminal 都能呼叫）
3. 把 `~/.ccc` 加進 user PATH
4. 帶 `--ext --vscode` 時一併安裝 highlighter 插件

舊版只在同一個 `~/.ccc` 放了 `ccc.ps1` + `ccc.cmd`，所以**重跑 `ccc-router install` 會就地覆蓋升級**：`ccc.ps1` 換成新的純路由版、補上 `ccc-router.*`，PATH 那筆已存在不變，無孤兒檔需要清。注意 `ccc init` / `ccc verify` 等舊子指令已移除（移到 `ccc-router`）。

`uninstall.ps1` 從 PATH 移除 `~/.ccc` 並刪除資料夾；當 `ccc-router uninstall` 是從已安裝的副本執行時，自身的 `ccc-router.cmd` 被 cmd.exe 鎖住，會 fallback 成 detached cmd 等本 terminal 釋放後再刪。

## Highlighter

高亮由 `editor/vscode-cccrouter-syntax/extension.js` 的 semantic tokens provider 提供（不是 tmLanguage）：`^n` → `cccPositional`，`$VAR` / `${VAR}` → `cccPlaceholder`。發佈走 GitHub Release，細節見 `editor/vscode-cccrouter-syntax/.instructions.md`。
